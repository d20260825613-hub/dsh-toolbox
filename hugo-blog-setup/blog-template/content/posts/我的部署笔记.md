## 目标

本地写完 Markdown，执行一次部署脚本就能上线，公网 HTTPS 直接打开，
零费用、零服务器维护。

## 实际步骤

1. 本地装 Hugo，建站
2. 用 Git 子模块引入 PaperMod 主题
3. 改 `config.toml`：站点名、简介、菜单、目录、分页
4. 写文章、本地预览
5. `hugo --minify` 构建出 `public/`
6. `wrangler pages deploy public` 上传到 Cloudflare

## 踩到的三个坑

### 坑一：构建出来是空白页 / 没有样式

原因是主题是 Git 子模块，但拉取代码时没取子模块内容。
确认 `themes/PaperMod` 里有真实文件，而不是一个空目录。

```bash
git submodule add https://github.com/adityatelange/hugo-PaperMod.git themes/PaperMod
```

### 坑二：中文标题的文章点开 404

少数环境的 URL 编码处理不一致。稳妥做法是给这类文章显式指定英文路径：

```yaml
url: "/posts/my-post/"
```

### 坑三：部署成功但页面还是旧的

`wrangler pages deploy` 上传的是**构建那一刻**的 `public/` 目录。
改了文章却忘了先重新构建，上线自然还是旧内容。
部署脚本里已经固化了「先 hugo 构建、再 wrangler 上传」的顺序。

## 结论

静态博客的发布链路其实非常短：
**Markdown → Hugo 构建 → 静态 HTML → Wrangler 上传 → Cloudflare 全球节点**。
真正需要小心的是「版本一致」和「重新构建」这两件事。
